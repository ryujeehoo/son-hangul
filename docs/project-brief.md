저장소: https://github.com/ryujeehoo/son-hangul (**공개 저장소**. 지금은 `.gitignore` 하나만 있다. 여기에 처음부터 만든다.)

## 공개 저장소 규칙 (가장 먼저 지킬 것)

- `.gitignore` 가 이미 있다. 키, 받는 사람 명단, 생성 결과물, 데이터셋, 모델 가중치, 내려받은 폰트, LLM 캐시를 막아 두었다. 새로 생기는 파일 종류가 있으면 규칙을 먼저 추가하고 나서 만든다. 규칙을 지우거나 약하게 바꾸지 않는다.
- API 키는 `.env` 에만 둔다. 코드, 테스트, 노트북 출력, 커밋 메시지 어디에도 키를 넣지 않는다. 커밋 전에 `git diff --cached` 에 `nvapi-` 가 없는지 확인한다.
- 실제 사람 이름이나 특징이 든 명단(`recipients*.csv`)과 생성 문구(`messages*.csv`)는 커밋하지 않는다. 예시는 `examples/` 에 가상의 이름으로만 만든다.
- README 용 샘플 이미지와 PDF는 `docs/samples/` 에만 둔다(이 폴더만 예외로 허용). 샘플에도 가상의 이름만 쓴다.
- AI Hub 같은 데이터셋은 재배포할 수 없으니 받는 방법만 문서로 남긴다.
- 폰트는 라이선스(OFL 등)가 재배포를 허락하는 것만 저장소에 넣고, 나머지는 스크립트로 내려받게 한다.

## 만들 것

한글 문장을 **실제 사람이 펜으로 쓴 것 같은 손글씨 이미지**로 바꿔 주는 프로그램을 만든다.
AI(LLM)는 "받는 사람에게 맞춘 따뜻한 한두 마디"를 지어내는 데 쓰고, 렌더러는 그 글을 손글씨처럼 그린다.

쓰임새는 두 가지다.

1. **게임 텍스처**: 게임 속 편지, 쪽지, 낙서, 메모 같은 소품. 번역체 문장이어도 "누가 손으로 적은 것 같은" 텍스처가 나와야 한다. 배경이 투명한 PNG, 종이 질감이 깔린 PNG 둘 다 필요하다.
2. **기업용 손편지 대량 출력**: 회사가 직원이나 고객에게 카드를 돌릴 때, 똑같은 문구를 찍어 내면 정이 없어 보인다. 받는 사람 정보(이름, 특징 한두 개, 요청사항)를 넣으면 LLM이 그 사람만을 위한 따뜻한 문장 한두 줄을 새로 만들고, 그걸 손글씨로 렌더링해서 **인쇄용 PDF**(카드 또는 A4 편지)로 뽑는다. 프린트했을 때 손으로 쓴 것처럼 보여야 한다.

핵심은 **인간미**다. 같은 글자가 매번 똑같이 찍히면 바로 폰트 티가 난다. 글자마다 조금씩 다르고, 줄이 살짝 기울고, 잉크가 조금씩 진하고 옅어야 한다.

## AI 부분: NVIDIA 무료 API (NIM)

유료 API는 쓰지 않는다. NVIDIA build.nvidia.com 의 무료 API를 쓴다. 예전에 내가 `ryujeehoo/lecture-summarizer` 에서 쓴 방식을 그대로 따른다:

- 엔드포인트: `https://integrate.api.nvidia.com/v1/chat/completions` (OpenAI 호환)
- 인증: `Authorization: Bearer $NVIDIA_API_KEY` (키는 `nvapi-...`, build.nvidia.com 에서 발급)
- 기본 모델: `meta/llama-3.3-70b-instruct`. 한국어 문장 품질이 더 좋은 모델이 카탈로그에 있으면 비교해 보고 기본값을 정하되, 환경 변수로 바꿀 수 있게 한다. 모델 이름은 카탈로그에서 직접 확인하고, 기억에 의존해 지어내지 않는다.
- 의존성 없이 표준 라이브러리 `urllib` 로 호출해도 되고, `openai` 패키지를 `base_url` 만 바꿔 써도 된다.
- `.env` 는 의존성 없이 읽고, `.env.example` 만 커밋한다. **키는 절대 커밋하지 않는다** (`.gitignore` 에 `.env`).
- 무료 티어라 요청 제한이 있다. 재시도(지수 백오프), 같은 입력에 대한 결과 캐시, 그리고 API 키가 없을 때 템플릿 문구로 대신하는 오프라인 모드를 넣는다.

문장 생성 규칙:
- 입력: 받는 사람 이름, 관계(고객/직원/동료 등), 특징 1~3개(예: "올해 입사", "등산 좋아함", "지난달 VIP 행사 참석"), 요청사항/어조, 길이(한 줄/두 줄/짧은 편지).
- 출력: 받는 사람의 특징을 **최소 하나는 자연스럽게** 녹인, 손으로 쓸 법한 짧고 따뜻한 문장. 광고 문구나 과장된 말투, 이모지는 피한다. 손글씨로 쓰기 좋은 길이로 제한한다.
- 같은 사람에게 여러 버전을 뽑을 수 있게 한다(`--variants 3`).

## 손글씨 렌더링

한글 손글씨는 학습 데이터 구하기가 어렵다. 그래서 단계를 나눈다.

### 1단계 (먼저 완성할 것): 손글씨 폰트 + 절차적 "인간화"

실제 사람 손글씨로 만든 무료 폰트를 바탕으로, 렌더링할 때 사람처럼 흔들리게 만든다.

- 폰트: Google Fonts 저장소(`github.com/google/fonts`, SIL OFL)에 있는 한글 손글씨 계열(예: Nanum Pen Script, Gaegu, Hi Melody, Gamja Flower, Poor Story, Single Day 등). 네이버 나눔손글씨 폰트도 라이선스 확인 후 선택지로. 폰트 파일은 스크립트로 내려받게 하고, 저장소에는 라이선스가 허락하는 것만 넣는다. 각 폰트의 라이선스를 README에 적는다.
- 글자 단위 변형: 회전, 크기, 기준선 위아래, 자간을 글자마다 조금씩 무작위로.
- 획 단위 변형: 글리프를 벡터 경로로 가져와(fontTools 또는 skia-python) 제어점을 저주파 노이즈로 살짝 비튼다. 그래서 **같은 글자도 나올 때마다 모양이 조금씩 다르게** 한다. 이게 폰트 티를 없애는 핵심이다.
- 줄 단위: 줄이 살짝 기울거나 휘고, 왼쪽 여백이 줄마다 조금씩 다르고, 뒤로 갈수록 글씨가 약간 커지거나 빨라지는 경향.
- 잉크: 펜 종류 프리셋(볼펜, 젤펜, 만년필, 연필, 사인펜). 획 굵기와 진하기 변화, 잉크가 고이는 점, 살짝 번짐, 연필은 거친 질감.
- 종이: 무지, 줄 노트, 모눈, 크라프트, 낡은 종이 프리셋. 줄 노트면 글씨가 줄을 대충 따라가게.
- 재현성: `--seed` 로 같은 결과를 다시 뽑을 수 있게.

### 2단계 (1단계가 끝난 다음): AI 손글씨 모델

- 몇 글자 샘플만으로 사용자 글씨체를 흉내 내는 한글 폰트 생성 모델(DM-Font, MX-Font, FontDiffuser 같은 계열)을 조사하고, 무료로 돌릴 수 있는지(Colab 등) 검토해서 `docs/` 에 정리한다. 가능하면 붙인다.
- 한글 손글씨 데이터는 AI Hub "한국어 글자체 이미지" 같은 데이터셋이 있지만 신청이 필요하다. 쓸 수 있는 데이터와 조건을 정리한다.
- **한글 데이터로 도저히 품질이 안 나오면 영어부터 한다.** 영어는 IAM On-Line 데이터로 학습된 손글씨 합성 모델(Graves 방식, 예: `sjvasquez/handwriting-synthesis`)이 공개되어 있어서 훨씬 자연스럽다. 영어 렌더러를 같은 인터페이스(`Renderer`)에 꽂을 수 있게 설계해 둔다.

## 출력

- PNG: 투명 배경(게임 텍스처용), 종이 배경 포함. 해상도 지정. 선택으로 노멀맵/러프니스 맵(잉크가 종이에 눌린 느낌).
- PDF: 300dpi 기준, 카드(A6, 엽서 100x148mm)와 A4 편지 템플릿. 여백, 받는 사람/보내는 사람 위치.
- 일괄 처리: CSV/JSON 으로 받는 사람 목록을 넣으면 한 사람당 파일 하나(또는 여러 장을 합친 인쇄용 PDF 하나). 생성된 문장은 `messages.csv` 로 함께 저장해서 사람이 검토하고 고친 뒤 렌더링만 다시 돌릴 수 있게 한다(LLM 단계와 렌더링 단계 분리).

## 인터페이스

- CLI 예시:
  - `handwrite render "오늘도 수고 많으셨어요" --font gaegu --pen gel --paper lined -o note.png`
  - `handwrite compose --name 김민수 --traits "올해 입사, 등산 좋아함" --tone 따뜻하게 --length 2줄`
  - `handwrite batch recipients.csv --format pdf --card a6 -o out/`
- 간단한 웹 UI(Gradio 또는 Streamlit)로 미리보기: 문장 입력/생성 → 폰트, 펜, 종이, 흔들림 정도 슬라이더 → 다운로드.

## 기술/품질 조건

- Python 3.11+. Pillow, numpy, fontTools 또는 skia-python, (필요하면) opencv, reportlab/PyMuPDF 로 PDF.
- 모듈 분리: `compose`(LLM 문장 생성) / `render`(손글씨) / `paper`(배경·질감) / `export`(PNG·PDF) / `cli`.
- 테스트: 문장 생성은 API를 목(mock)으로, 렌더러는 시드 고정 결과가 안정적인지, 같은 글자가 매번 다르게 나오는지, 한글 자모 조합(겹받침 포함)과 영문·숫자·문장부호가 깨지지 않는지 확인.
- README 는 한국어로: 설치, API 키 받는 법(build.nvidia.com), 예시 이미지(실제로 생성한 결과물을 `docs/samples/` 에 넣고 README 에 첨부), 폰트 라이선스.
- 사용 윤리 한 단락: 특정 실존 인물의 필체를 본인 동의 없이 흉내 내거나 서명을 위조하는 용도로 쓰지 말 것.

## 진행 방식

1. 먼저 계획(디렉터리 구조, 단계별 마일스톤)을 짧게 제시하고 바로 1단계 구현에 들어간다.
2. 1단계가 "프린트해서 봤을 때 손글씨 같다" 수준이 될 때까지 샘플을 직접 생성해서 눈으로 확인하고(이미지로 보여 줘), 폰트 티가 나는 부분을 고친다.
3. 작업 단위마다 커밋하고 푸시한다. 커밋 메시지는 한국어로.
4. 막히는 부분(데이터, 라이선스, 모델 품질)은 지어내지 말고 무엇이 막혔는지와 대안을 알려 준다.
